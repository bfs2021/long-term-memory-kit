# The Digest Ships as Word Files, and ltm Never Deletes in the Tenant

`ltm digest` writes markdown, but the files that reach SharePoint are `.docx`, converted by `pandoc` in the Bank's workflow. Microsoft's docs list semantic retrieval for M365 Copilot only on `.doc`, `.docx`, `.pptx`, `.pdf`, `.aspx`, and `.one` files, so a markdown Digest would get keyword matching at best. Modern SharePoint pages also qualify, but publishing them means the Pages API and a page per Record. Converting in the workflow keeps Word-format code and its dependencies out of `ltm`.

`ltm` never deletes a file in a client's SharePoint. When a Digest file drops out of the set (a Facet loses its last accepted Record, or a Bank switches between one file and `--split facet`), `ltm digest --out <dir>` overwrites it with a placeholder naming its replacement, and the publish uploads that placeholder. Copilot keeps citing a file left behind with old content, including any expired Exception in it. A delete in a client's tenant is a write `ltm` can't take back, while a placeholder is just an overwrite. `<dir>` is committed to the Bank, so `ltm` works out what to replace from git without ever reading SharePoint.
